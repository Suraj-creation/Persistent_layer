# Persistent learner-state and retrieval contract

## What is observed and what is inferred?

The original response is an observation. The extracted quote is an exact span of that observation. The claim, criterion judgments, misconception hypothesis and confidence are model inferences. Keeping those fields separate prevents a fluent explanation generated by the tutor from becoming learner evidence.

The NLP record includes original and normalized text, original-text token/sentence offsets, lexical keywords and uncertainty/negation cues. The original text is never replaced by normalization. Reference documents use an exact content digest so case-sensitive changes in code or equations are retained. Response duplicate detection preserves case as well.

## Evidence validation

The server resolves the active saved question; the browser cannot supply a different rubric. A schema-constrained model checks only the assigned concept. The source quote must exist verbatim, rubric IDs must form a disjoint complete met/missing partition, citations must belong to retrieved learning material, and contradiction references must identify existing hypotheses in this concept. Unknown identities, fabricated quotations and malformed assessments are rejected with a bounded retry.

Passing validation does not establish the truth of an interpretation. It establishes a checkable data contract and source linkage. Confidence is explicitly uncalibrated.

## Numerical state

Each new concept starts with alpha = 1 and beta = 1. The mean of this neutral Beta prior is 0.5; an unassessed concept is displayed as unassessed, not as a 50% test score.

For an informative observation:

- rubric coverage = met criteria / total criteria;
- informativeness = min(original-text token count / 16, 1);
- novelty = 1 for a new explanation, 0.15 for an identical normalized-whitespace response in this concept;
- weight = model confidence × informativeness × novelty;
- delta alpha = weight × coverage;
- delta beta = weight × (1 − coverage), multiplied by 0.15 for an evidenced calculation slip;
- estimate = alpha / (alpha + beta);
- uncertainty = sqrt(alpha × beta / ((alpha + beta)^2 × (alpha + beta + 1))).

Ambiguous observations, confidence below 0.55, or fewer than four tokens hold alpha/beta. All observations still retain provenance. Informative counts exclude identical repeated responses. These thresholds are versioned engineering heuristics requiring experimental calibration.

The state event stores every input, factor, delta and resulting parameter. Snapshot IDs are immutable identities; replayable numerical updates do not depend on generated prose.

## Missing criteria and candidate beliefs

A missing criterion is stored by a stable fingerprint of its description, with supporting evidence references. It remains open across questions and conversations until a later rubric explicitly includes and satisfies that same criterion. Success on another criterion, even one using the same short rubric ID, cannot clear it.

Candidate misconceptions retain supporting and contradicting evidence IDs and an uncalibrated reinforcement score. Repeated support may change their status to recurring. Only explicit, validated contradiction references from the same concept can weaken a belief. A correct answer does not indiscriminately dismiss every hypothesis.

Coaching is an intervention, not evidence. It changes neither alpha/beta nor criterion status. A subsequent learner explanation must address the gap.

## Retrieval and generation

Documents are chunked with overlapping original-text ranges. Learning material and learner evidence have distinct source kinds. FTS5 indexes normalized text with Porter/Unicode tokenization; BM25 ranks matches within the exact learner/topic scope. Scores are ranking values, not confidence. If terms do not match, recent scoped passages are returned with a recorded fallback method.

Student evidence is a diagnostic signal, not a source of educational facts. Only supplied material or the explicitly labeled model-authored reference can ground a question's factual rubric.

The deterministic planner reads SQLite state and chooses a concept, difficulty, question kind and diagnosis/repair/transfer objective. Repair plans include exact earlier missing criteria with stable IDs. The model must retain those criteria while creating a fresh task. This makes a later check traceable to a specific earlier gap.

The `focused-adaptive-planner-v2` policy narrows repeated repairs to one remaining criterion and rotates contrast, debugging, application and guided-practice tasks. The evidence update formula remains `criterion-weighted-state-v1`. Stored earlier question plans retain their original version.

The generator receives only the saved plan, saved state, retrieved passages and prior question prompts. The exact input, snapshot ID, hash, prompt version, model and latency are retained. The server validates target, kind, citations, criterion identities and prompt novelty before activating a question. There is no fixed-question fallback.

## Transactions and recovery

Topic state is shared across conversations for one learner/topic. Optimistic snapshot/version checks prevent a slow model call from overwriting newer state. SQLite write transactions are short; inference happens outside them. Idempotency keys protect creation and answer submission. A conflicting retry or stale question returns 409.

A validated answer, evidence chunk, state snapshot and conversation update commit together. Failed storage rolls them back together. Generating the next question is a separate recoverable step: if it fails, the committed answer is not lost or duplicated on retry.

## Reporting progress

The report joins saved questions, exact responses, rubric judgments, state events, retrieval and next-question plans. Topic estimates can include prior conversations; the conversation's own contribution is the sum of only its own recorded deltas.

Evidence of progress requires a prior open criterion to be explicitly addressed in a new question, with a non-duplicate learner explanation. A generated hint, elapsed conversation length, friendly feedback or a higher average alone cannot establish improvement. Unknown/unassessed concepts remain visible. Reports are structured projections of stored records rather than unconstrained model-generated diagnoses.
